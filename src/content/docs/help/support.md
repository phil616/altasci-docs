## 提交前检查

先在文档搜索中输入错误代码或关键现象，查找已有处理步骤。服务访问类错误（`E001` 至 `E008`）先按 [服务访问错误代码](/docs/errors/access-errors/) 的索引与通用排查步骤自查；对订单提交超时等情况，先检查请求是否已成功受理。

## 收集必要信息

| 信息 | 示例 |
| --- | --- |
| 发生时间 | 2026-10-21T10:30:00+08:00 |
| 使用环境 | sandbox |
| 项目编号 | DEMO-PROJECT-001 |
| 请求编号 | demo-request-001 |
| 错误代码 | BUSINESS_STATE_CONFLICT |
| 期望结果 | 取消待处理订单 |

## 请求模板

```text
标题：取消订单时提示状态冲突
环境：sandbox
项目 / 订单：DEMO-PROJECT-001 / DEMO-ORDER-001
发生时间：2026-10-21T10:30:00+08:00
请求编号：demo-request-001
复现步骤：打开订单详情 → 选择取消 → 收到状态冲突
期望结果：确认当前状态并了解后续处理方式
```

提交日志前移除令牌、密码、私钥与个人敏感信息。证书问题提供公开证书信息和错误现象即可，排查时无需发送私钥。

## 后续跟进

通过团队实际使用的支持渠道发送请求，并在同一问题记录中补充进展。本示例不承诺具体响应时间，也不包含在线工单功能。
