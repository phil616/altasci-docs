## 适用范围

本板块介绍 AltasCI 的持续集成与交付实践，面向需要了解构建、部署和应用配置方式的开发者。内容按应用形态、构建平台、部署目标、凭据和连接方式组织。

文中的命令、域名、应用名和仓库路径是为公开说明整理的示例，使用前需要替换并确认环境配置。这些文档不提供部署权限，也不代表本文档网站能够执行流水线或操作服务器。

## CI 与 CD 的分工

持续集成（CI）负责在代码变更后运行检查与构建，产出可交付的静态文件、程序包或容器镜像。持续交付（CD）将制品准备到可发布状态；持续部署则进一步自动发布到运行环境。是否自动进入生产环境，由项目的发布流程决定。

在本文介绍的流程中，CI 关注“构建出了哪个版本”，CD 关注“将该版本交付到哪里、如何加载配置并确认运行结果”。

## 一次发布的主要步骤

```text
提交代码并触发流水线
        ↓
安装依赖，执行项目已有检查并构建
        ↓
产出带版本标识的制品
  ├─ 静态文件 → 交付到静态托管或 CDN
  └─ 容器镜像 → 推送到镜像仓库
        ↓
确认部署目标、连接通道及运行时配置
        ↓
部署服务并检查版本、启动状态与访问结果
```

静态站点通常直接通过托管平台的部署工具交付；运行在 Linux 主机上的应用，还需要考虑主机连接、配置同步和服务管理。二者不必使用完全相同的发布步骤。

## 识别应用、主机与制品

| 标识 | 作用 | 使用时注意 |
| --- | --- | --- |
| AppID | 应用的唯一标识，用于关联配置材料与部署对象 | 同一应用在配置路径、同步命令和发布记录中保持一致 |
| NodeID | 部署目标主机的管理标识 | 与系统 hostname、IP 地址分别记录，不根据名称推断连接参数 |
| 提交 SHA 或制品摘要 | 标识代码与构建产物版本 | 部署记录应能追溯到实际使用的制品 |

AppID 和 NodeID 是 AltasCI 的管理约定，不是各家 CI 平台的通用内置字段。实际可用的标识与访问权限，以接入项目的配置为准。

## 建议阅读顺序

首次了解流程时，先阅读[应用形态与部署方式](/docs/cicd/deployment-types/)，再选择[CI 平台](/docs/cicd/ci-platforms/)。准备编写 CNB 配置时，继续阅读[流水线配置](/docs/cicd/cnb-pipelines/)；涉及服务器发布时，再核对[部署目标](/docs/cicd/deployment-platforms/)、[凭据](/docs/cicd/credentials/)和[连接通道](/docs/cicd/connections/)。

AI Agent 可以先 GET `/llm.txt` 获取完整索引，再读取本板块各篇文章的 `.md` 地址，例如 `/docs/cicd/cnb-pipelines.md`。编写配置前，应先确认目标项目实际使用的平台、目录、变量和部署方式。
