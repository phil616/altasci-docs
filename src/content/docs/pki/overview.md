## 什么是 PKI

公钥基础设施（PKI）通过证书、信任配置和管理流程，帮助系统把公钥与特定主体关联起来。证书验证时需要结合信任锚、有效期、用途与其他约束判断是否接受。

本文介绍本站涉及的两类公钥体系：用于 TLS 等场景的 X.509 证书体系，以及用于消息、文件签名与加密的 OpenPGP 体系。两者都需要保护私钥、核对公钥身份并处理更新与撤销，但使用的数据格式和信任规则不同。

## 核心术语

| 术语 | 含义 |
| --- | --- |
| 公钥 | 可提供给其他参与方的密钥部分 |
| 私钥 | 由持有者保护，用于相应密码操作的密钥部分 |
| 证书 | 将公钥与主体信息关联的签名数据；X.509 与 OpenPGP 的结构和验证规则不同 |
| CA | 证书颁发机构 |
| 信任锚 | 验证过程中预先信任的起点 |
| 证书链 | 连接目标证书与信任锚的证书路径 |

## GPG、GnuPG 与 OpenPGP

OpenPGP 是规定密钥、签名及加密消息等数据格式的标准。GnuPG 是实现 OpenPGP 的软件，`gpg` 是其处理 OpenPGP 数据的命令行工具，日常也常将它简称为 GPG。OpenPGP 与 X.509 的数据不能直接互换，导入 OpenPGP 公钥不会让浏览器信任某个 HTTPS 网站。

OpenPGP 常用于核对文件或消息签名，以及向指定收件人发送加密内容。具体组织是否提供某项签名或加密服务，仍以其公布的用途与策略为准；支持某种密码功能不代表已建立对应业务服务。

### 公钥、私钥与密钥环

公钥可以公开分发，私钥由持有者保管。发送者使用收件人的公钥加密，收件人使用对应私钥解密；签名者使用自己的私钥签名，接收者使用对应公钥验签。公钥不能用来恢复对应私钥。

GnuPG 使用本地密钥环等存储管理公钥、私钥及相关数据。导入一个公钥只是让工具能够找到它，不表示已确认持有者身份，也不会自动赋予它信任。

### 主密钥、UID 与子密钥

一份通常称为“OpenPGP 公钥”的发布材料，可以包含主公钥、用户标识（UID）、公钥子密钥和相关签名。UID 中的姓名、邮箱是身份声明，单凭文字内容不能证明其真实性。

主密钥通过自认证签名将 UID 与自身关联，通过绑定签名将子密钥与自身关联。主密钥适合承担身份与认证职责，日常操作可交给用途不同的子密钥，以便分别轮换和管理。是否采用这种分工取决于实际密钥配置，并非所有 OpenPGP 密钥都有相同结构。

| 用途标记 | 含义 | 典型操作 |
| --- | --- | --- |
| `[C]` | 认证（Certify） | 认证 UID 与公钥的关联等密钥管理操作 |
| `[S]` | 签名（Sign） | 对文件或消息生成数字签名 |
| `[E]` | 加密（Encrypt） | 供发送者加密，持有对应私钥者解密 |
| `[A]` | 鉴别（Authenticate） | 在支持的协议与工具中进行身份鉴别 |

验证人员签名时，实际签名者可能是 `[S]` 子密钥。应检查它与预期主密钥的绑定关系，不能因为子密钥指纹与主密钥不同就判定签名错误。

## 文件校验、指纹与签名

这三种核对回答不同的问题：

| 核对方式 | 能确认什么 | 仍需确认什么 |
| --- | --- | --- |
| 文件 SHA-256 | 下载字节是否与所比较的校验值一致 | 校验值本身是否来自可信来源 |
| 完整密钥指纹 | 当前公钥是否为预期的那把密钥 | 指纹与真实主体的关联是否已独立核实 |
| 文件或消息签名 | 签名是否与原文及该公钥匹配 | 签名者身份、用途、有效期、撤销状态及业务权限 |

OpenPGP 指纹由密钥数据计算得到，不等于 `.asc` 下载文件的 SHA-256。公钥文件增加认证签名后，文件校验值可能改变，而主密钥指纹保持不变。不同版本的 OpenPGP 密钥可能使用不同长度的指纹，应比较完整值，不要只核对前后几位或截断的 Key ID。

文件签名可与原文分开保存，称为分离签名。验签时需要配套的原文、签名和签名者公钥。加密主要保护内容机密性，签名用于核对来源与内容完整性；仅加密并不能证明发送者身份，仅签名也不会隐藏原文。

## 认证关系与信任模型

### 自认证、第三方认证与信任签名

自认证说明该 UID 由相应密钥持有者声明；它不能单独证明姓名、邮箱或任职关系。第三方认证签名表示认证者对“UID 与公钥的关联”作出了签名声明，是否接受该声明取决于你对认证者及其核验流程的信任。

信任签名还可表达对认证者能力的委托，并携带深度、范围等约束。它与对业务文件的签名用途不同，不能将“机构认证过此公钥”直接等同于“机构批准了此人签署的所有内容”。

OpenPGP 可以使用直接核对指纹、信任网（Web of Trust）或组织认证链等方式建立信任，不要求所有使用者都依赖同一个中央 CA。本站的企业根 → 员工认证机构 → 人员公钥属于具体组织配置，不是所有 GPG 用户必须采用的通用层级。

### ownertrust 与 validity

在 GnuPG 的信任网模型中，ownertrust 表示你在本机对某密钥持有者认证其他密钥的能力给予多少信任；validity 表示工具结合认证签名、信任设置及所选模型，计算出的公钥与 UID 关联的有效性。两者含义不同。

ownertrust 通常保存在本地信任数据库中，不会随普通公钥导出传播。`[unknown]` 表示尚未建立足够的本地信任依据，不等于签名一定损坏；`[full]` 是本地计算的充分有效状态，不是实时在职或业务授权证明。`[ultimate]` 是很强的本地信任设置，不应作为消除警告的常规办法。

因此，验签显示 `Good signature` 后，仍应检查完整指纹、认证关系与使用策略。独立核对信任锚应使用已确认身份的另一渠道，同一网站上的公钥、指纹和校验清单不能相互充当独立证明。

## X.509 与 OpenPGP 对照

| 项目 | X.509 证书体系 | OpenPGP 体系 |
| --- | --- | --- |
| 常见场景 | TLS / HTTPS、客户端证书认证等 | 文件与消息签名、加密通信等 |
| 身份信息 | 证书主体、Subject Alternative Name 等字段 | 与主密钥关联的 UID 等数据 |
| 认证方式 | CA 签发证书，按认证路径与约束验证 | 自认证、第三方认证及所选信任模型 |
| 信任起点 | 系统、应用或管理员配置的信任锚 | 独立核对的公钥、直接信任或组织信任锚等 |
| 撤销信息 | 可通过 CRL、OCSP 等机制提供，是否检查取决于实现与策略 | 通过更新公钥或撤销签名等材料分发，客户端须取得相关更新 |
| 常见文件 | PEM / DER 编码的证书或证书链 | ASCII Armor 或二进制编码的密钥、签名与消息 |

`.asc` 表示常见的 ASCII Armor 文件扩展名，并不保证内容一定是公钥；它也可能包含签名或加密消息。处理前应核对实际内容类型，不能只看文件名。

## 有效期、撤销与轮换

主密钥和子密钥可以具有各自的有效期。到期是时间约束，撤销则用于声明密钥或认证关系不应继续被接受，例如私钥泄露或密钥替换。判断历史签名时，还需结合签名时间、撤销原因与适用策略，不能将“今天到期”直接解释为“所有历史签名都无效”。

OpenPGP 更新可以包含新的子密钥、有效期信息或撤销签名。客户端应从已核实的来源获取更新并重新导入；未收到撤销信息不能证明密钥尚未撤销。轮换时还应保留解密历史数据所需的旧私钥和必要备份，新密钥不能解密原本只加密给旧密钥的内容。

## 标准参考

X.509 证书、CRL 与认证路径验证的基础说明见 [RFC 5280](https://www.rfc-editor.org/info/rfc5280/)。实际实现还应结合所用协议、工具及适用的后续规范。

OpenPGP 数据格式见 [RFC 9580](https://www.rfc-editor.org/info/rfc9580/)。GnuPG 的认证、信任签名及密钥管理操作见 [密钥管理手册](https://www.gnupg.org/documentation/manuals/gnupg/OpenPGP-Key-Management.html)，状态标记见 [Trust Values](https://www.gnupg.org/documentation/manuals/gnupg/Trust-Values.html)，信任模型配置见 [GPG Configuration Options](https://www.gnupg.org/documentation/manuals/gnupg/GPG-Configuration-Options.html)。
