## 确认问题范围

记录应用地址、时间、客户端版本和完整错误信息。以下清单演示排障文档的组织方式，不替代具体客户端或协议的验证规则。

## 检查清单

| 检查项 | 需要确认的内容 |
| --- | --- |
| 时间 | 客户端时间正确，证书处于有效期内 |
| 服务身份 | 对于 TLS，访问域名与证书允许的身份匹配 |
| 证书链 | 提供所需中间证书，可构建有效路径 |
| 信任配置 | 客户端信任适用的信任锚 |
| 用途与约束 | 符合实际使用场景 |
| 撤销状态 | 按实际策略获取并处理撤销信息 |

## 更新后仍提示旧证书过期

核对服务实际返回的证书与部署记录，检查是否存在未更新节点，或应用尚未重新加载配置。

## 只有部分客户端验证失败

对比各客户端的信任配置、证书链处理与时间。应修正证书、链或可信配置，避免通过关闭验证掩盖问题。

## 提示域名不匹配

确认实际访问地址与证书中的身份信息。域名变更后，应按实际申请流程取得适用证书。

## 保留排查结果

记录已检查内容与复现步骤，必要时使用 [支持模板](/docs/help/support/)，无需附上私钥。

认证路径验证基础见 [RFC 5280](https://www.rfc-editor.org/info/rfc5280/)。TLS 身份检查还需遵循客户端所实现的相应协议规则。
