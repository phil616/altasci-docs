## 适用范围与浏览器区别

当网站启用双向 TLS（mTLS）时，服务器不仅向浏览器出示 HTTPS 服务器证书，还可能要求浏览器提供**客户端证书及对应私钥**来证明访问者身份。导入证书不等于自动获得网站授权，是否允许访问仍由服务端决定。

在常见的桌面环境中，两种浏览器使用客户端证书的方式不同：

| 浏览器 | 常见客户端证书来源 | 推荐导入方式 |
| --- | --- | --- |
| Firefox | 默认使用 Firefox 自身的证书管理器 | 在“您的证书”中导入 `.p12` / `.pfx` |
| Chrome（Windows） | Windows 当前用户的证书存储 | 导入到“当前用户 → 个人” |
| Chrome（macOS） | macOS 钥匙串中的个人身份 | 导入到“登录”钥匙串 |

**例外：** Firefox 在 Windows / macOS 上也可以通过 `security.osclientcerts.autoload` 等设置或组织策略读取操作系统的客户端证书。因此“Firefox 必须重复导入”并非对所有安装环境都成立。本文先介绍最通用的 Firefox 手动导入流程。

本文针对**桌面版 Firefox 与 Windows / macOS 上的 Chrome**。Linux 版 Chrome、ChromeOS 和移动平台的证书管理方式有所不同，不适用下述 Windows / macOS 步骤。

## 一、准备客户端证书

### 确认文件类型

通常管理员会提供一个受密码保护的 `.p12` 或 `.pfx` 文件（PKCS#12 格式）和**导入密码**。该文件应包含：

- 签发给你的**客户端 X.509 证书**；
- 与该证书公钥匹配的**客户端私钥**；
- 可选的中间 CA 证书链。

请先从可信渠道核对文件来源与预期的证书身份，并确认文件未过期。私钥有时被配置为不可导出并保存在硬件令牌或操作系统内；这种情况下应遵循对应的企业 / 设备配置流程，不能按本文导出成 P12。

**注意：** [CA 证书下载](/docs/pki/downloads/) 提供的是**公开的 CA 证书和证书链**，不包含你的客户端私钥。下载 CA 文件本身不能代替个人客户端证书，也不应把客户端证书导入“受信任的根证书颁发机构”存储区。

### 只有 PEM / CRT / KEY 时：转换为 P12

若管理员提供的是分开的 `client.crt`（证书）和 `client.key`（匹配的私钥），可在安装了 OpenSSL 的本机上执行：

```bash
openssl pkcs12 -export \
  -inkey client.key \
  -in client.crt \
  -out client.p12 \
  -name "mTLS Client"
```

按照提示设置**强导入密码**，然后使用生成的 `client.p12`。命令中的文件名为示例，按实际收到的文件替换。该命令不会把密码写入命令行历史。

若服务要求客户端同时发送中间证书，可在打包命令中添加 `-certfile intermediates.pem`，其中放置正确的**中间 CA 证书**；不要随意混入无关证书或将 CA 当作客户端身份导入。

可检查 P12 文件结构（不会输出私钥明文）：

```bash
openssl pkcs12 -in client.p12 -info -noout
```

此命令会要求输入导入密码。单纯把 `.pem` / `.crt` 文件**改名**为 `.p12`，不会将其转换为 PKCS#12，也不会补出缺失的私钥。

## 二、导入 Firefox

Firefox 通常在自己的证书库中管理用户证书。以下操作适用于常见的桌面版 Firefox。

1. 打开 Firefox，点击右上角菜单 **☰ → 设置（Settings）**。
2. 进入 **隐私与安全（Privacy & Security）**，找到 **证书（Certificates）**；也可以在设置页搜索 `cert`。
3. 点击 **查看证书（View Certificates）**。
4. 在证书管理器中切换到 **您的证书（Your Certificates）**。
5. 点击 **导入（Import）**，选择收到的 `.p12` / `.pfx` 文件。
6. 按提示输入 **PKCS#12 导入密码**。如果 Firefox 为自己的证书库设置了主密码（Primary Password），也可能先要求输入该密码；**两个密码可能不同**。
7. 导入完成后，检查“您的证书”中出现预期证书，并核对主体与有效期。

**验证：** 访问管理员指定的 mTLS 网站。如果服务器要求客户端证书且浏览器需要用户选择，Firefox 会显示证书选择对话框；选择匹配的证书后继续。若已配置自动选择或不存在可用证书，**不一定会弹出选择框**，应以实际连接及服务端认证结果为准。

如已在 Windows / macOS 的系统证书库配置客户端证书，可咨询管理员是否启用 Firefox 的操作系统客户端证书支持；不要为了消除问题就随意更改企业管理策略。

## 三、导入 Chrome（Windows）

Chrome 在 Windows 上通常通过系统证书存储使用客户端身份。推荐导入到**当前用户的“个人（Personal）”存储区**，而不是根 CA 信任区。

1. 在资源管理器中找到 `.p12` / `.pfx` 文件，双击打开 **证书导入向导**。
2. 在存储位置选择 **当前用户（Current User）**，然后继续。
3. 确认文件路径，输入 **导入密码**。除非确有备份或迁移需要，否则不必启用“标记此密钥为可导出”。
4. 在证书存储步骤，可先选择 **根据证书类型，自动选择证书存储**；若要手动指定，请将**客户端证书及私钥**导入 **个人（Personal）** 存储区。
5. 完成向导，确认显示导入成功。
6. 按 `Win + R`，输入 `certmgr.msc`，打开**当前用户**证书管理器，在 **个人 → 证书** 中确认客户端证书已存在且关联私钥。
7. 关闭所有 Chrome 窗口并重新打开，访问管理员指定的 mTLS 网站进行验证。

如需从 Chrome 入口查看证书，可打开 **设置 → 隐私和安全 → 安全 → 管理证书（Manage certificates）**，或在地址栏输入 `chrome://certificate-manager`。**不同 Chrome 版本的界面可能不同**，请寻找本地证书 / 系统证书的入口；`certmgr.msc` 是 Windows 上定位当前用户证书的直接方式。

请注意：Chrome 的内置证书管理页面也涉及**网站服务器证书和根证书信任**；这些设置与“个人”中的 mTLS 客户端身份不是一回事。

## 四、导入 Chrome（macOS）

Chrome 在 macOS 上通常通过系统钥匙串使用客户端证书与私钥。

1. 双击收到的 `.p12` / `.pfx` 文件，按系统提示使用 **钥匙串访问（Keychain Access）** 导入。也可以打开钥匙串访问后选择导入项目。
2. 选择 **登录（login）** 钥匙串（如果出现选择提示）。
3. 输入证书文件的 **PKCS#12 导入密码**，完成导入；系统也可能要求 macOS 用户密码来授权操作。
4. 在钥匙串访问中选择 **登录 → 我的证书（My Certificates）**，检查该身份是否包含客户端证书和关联私钥。
5. 关闭所有 Chrome 窗口并重新打开，访问指定的 mTLS 网站。首次使用私钥时，macOS 可能提示确认 Chrome 的访问权限。

**不要为使用客户端证书而例行将其设为“始终信任（Always Trust）”。** 通常保持 **使用系统默认（Use System Defaults）** 即可。客户端身份的导入与服务器 HTTPS 信任是两件事；若确实需要信任内部服务器 CA，应先独立核对 CA 身份，并按管理员明确的安全策略操作。

## 五、验证及常见问题

### 1. 访问网站时没有出现证书选择框

这并不一定表示导入失败。请依次确认：

- 目标地址确实启用了 mTLS，且服务端在 TLS 握手中请求客户端证书；普通 HTTPS 网站不会主动弹出选择框。
- 浏览器可能自动选择证书，或依据当前策略跳过询问。
- 证书是否仍在有效期内，是否有**对应私钥**，是否具有适用的 **Client Authentication（clientAuth）** 用途，并符合服务端接受的签发 CA / 证书策略。
- Firefox：查看 **您的证书**，核对当前浏览器配置文件；如使用系统证书，核实是否启用了系统客户端证书支持。
- Windows Chrome：打开 `certmgr.msc`，检查 **当前用户 → 个人 → 证书**，不要只检查 **受信任的根证书颁发机构**。
- macOS Chrome：检查 **登录 → 我的证书** 中是否有包含私钥的身份，必要时检查系统私钥访问权限。

### 2. 浏览器提示网站证书“不受信任”或“无效”

首先区分错误对象：

- **服务器 HTTPS 证书错误**：浏览器无法验证网站证书、主机名或其 CA 链。请核实访问域名、证书有效期和服务器配置。若使用内部 CA，仅在**独立核实 CA 指纹并获得明确授权**后按要求配置服务器 CA 信任；**不要通过关闭证书验证绕过警告**。
- **客户端证书认证失败**：即使网站服务器证书有效，服务端仍可能因客户端证书不在允许范围内、证书链不完整、已过期或已撤销、账号未获授权等原因拒绝请求。需要由管理员结合服务端日志排查。

### 3. Firefox 导入失败或证书没有出现在“您的证书”

- 核对 P12 文件的**真实格式**与导入密码；不要仅重命名扩展名。
- 确认证书与匹配的私钥包含在 P12 中；只有公开证书的文件不能作为个人身份导入。
- 若 Firefox 设置了 **主密码**，区分主密码和 P12 文件密码。
- 如 P12 使用浏览器不支持的加密算法，请联系证书签发方重新导出兼容的文件；**不要为了兼容而无条件改用弱加密**。

### 4. 导入成功但网站仍拒绝访问

检查客户端证书的用途、有效期、服务端要求的 CA 链和账号授权。若出现类似 `403`、`bad certificate` 或 `certificate required` 的错误，仅凭网页文案往往无法确定是哪一步失败，应由管理员查看反向代理与服务端日志。

## 六、安全提醒

- **P12 / PFX 通常包含私钥，属于敏感凭据。** 不要发送给无关人员、上传到在线转换网站或提交到 Git 仓库。
- 尽量通过受信任的渠道获取证书和导入密码；如需传输，避免把密码与证书明文放在同一条消息中。
- 如果因打包需要生成临时 `client.p12`，完成导入后应按组织的安全策略处理本地临时文件与原始私钥文件。
- 怀疑私钥泄露时，及时通知管理员进行撤销和重新签发；**删除浏览器中的证书不等于撤销证书**。
